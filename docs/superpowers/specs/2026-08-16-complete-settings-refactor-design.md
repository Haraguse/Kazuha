# 完整设置页面与功能重构设计

## 目标

将 Python 设置页面的全部用户可见功能迁移到原生 Avalonia/C# 设置窗口。页面保留 12 个纵向导航分类，所有配置使用强类型 C# 模型，所有可执行操作通过独立服务完成。

## 用户分类

导航使用稳定的分类 ID，不使用裸字符串索引回退：

1. `general` 常规
2. `personalization` 个性化设置
3. `fonts` 全局应用字体
4. `toolbar` 插件 / 工具栏
5. `linkage` 联动
6. `built-in` 内建功能
7. `pen` 画笔
8. `window` 窗口
9. `statusbar` 状态栏
10. `storage` 存储、档案和备份
11. `notifications` 通知
12. `about` 关于

每个分类必须有真实 ViewModel、真实 Avalonia 页面、唯一路由和可验证的控件行为。不存在的页面不得回退到常规页面。

## 配置状态

`LuminaliumConfig` 是唯一配置事实来源。设置页面不得维护主题、语言、启动画面、Overlay 或工具栏的独立业务副本。

`SettingsCoordinator` 负责：

- 克隆当前配置并执行候选修改
- 校验枚举、范围、路径和数组内容
- 执行必要的运行时或平台副作用
- 原子保存配置
- 保存失败或副作用失败时恢复旧配置和控件状态
- 发布带分类 ID 和变更字段的设置事件

设置档案切换必须即时加载目标档案并刷新主题、语言、Overlay、工具栏、PPT、画笔、通知和窗口消费者。

## 服务边界

- `ProfileService`：档案 CRUD、活动档案和即时切换
- `ConfigurationBackupService`：用户备份 CRUD、元数据和恢复
- `StorageService`：容量统计、目录清理和路径安全
- `DiagnosticService`：版本、系统、配置 schema、路径和日志摘要
- `UpdateOrchestrator`：复用现有更新后端，补齐更新源和自动检查设置
- `SettingsCoordinator`：统一配置事务和运行时事件

页面 ViewModel 只负责展示状态、验证用户输入和调用服务，不直接操作 JSON、注册表、文件系统或更新器。

## 运行时生效

- 主题、语言、字体、工具栏、Overlay、状态栏、通知和 PPT 限流即时生效。
- 档案切换即时刷新所有运行时消费者。
- 画笔模式从下一次进入书写状态生效，不打断当前笔迹会话。
- 原生标题栏和需要窗口重建的样式显示明确的重新打开窗口提示。
- PowerPoint 翻页继续 COM 优先，虚拟键仅作回退，不抢占前台窗口。

## 错误处理与安全

- 配置、档案、备份和更新操作返回结构化成功/失败结果。
- 文件系统错误、权限错误、更新校验失败和平台副作用失败必须显示用户可理解的错误信息。
- 备份恢复前保留当前配置快照，恢复失败自动回滚。
- 不保存或显示明文密码，不把令牌、密钥或敏感路径写入日志。
- 清理操作只能作用于应用管理目录，禁止任意路径删除。

3. 完成工具栏高级编辑、Overlay 全部字段和运行时刷新。

## 验收标准

- 12 个导航项唯一，全部显示真实页面，不允许路由回退。
- Python 可见设置均有 C# 控件或明确的原生语义转换。
- 档案、备份、存储清理、诊断和更新按钮实际可执行。
- 变更即时保存，失败时控件、配置和运行时恢复旧状态。
- Release 构建零错误零警告。
- 全量单元测试通过，并完成设置窗口逐分类桌面冒烟验证。
