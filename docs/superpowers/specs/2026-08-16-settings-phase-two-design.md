# 设置页面第二阶段迁移设计

## 目标

将 Python 项目 `Lmn-copy` 中的常规、个性化、Overlay、工具栏和 PPT 联动设置迁移到 Avalonia/C# 项目，并让支持运行时刷新的设置即时保存和生效。

## 范围

### 常规

- 语言
- 开机自启
- URL 协议
- 禁用界面动画
- 异常退出处理及处理模式
- 自动显示 Overlay
- 兼容模式
- PPT 翻页频率上限

### 个性化

- 应用主题模式
- 强调色
- 全局字体
- 启动画面显示模式、样式、详细进度和时间范围
- Overlay 主题标识

### Overlay

- 目标屏幕
- 工具栏位置
- 翻页栏位置
- 安全区
- 主界面与弹出界面缩放
- 工具栏与翻页栏透明度
- 透明度同步
- 严格边缘对齐
- 工具栏自动半收起
- 置顶策略
- 层级检查间隔
- 状态栏及状态项显示

### 工具栏

- 清除、聚光灯、板中板和计时器显示开关
- 工具文字显示
- 工具提示显示
- 工具顺序
- 禁用工具集合
- 快速启动应用列表配置持久化

### PPT 联动

- 自动处理墨迹
- COM 与自研画笔模式
- 翻页频率限制
- 自研画笔宽度、颜色、荧光笔和橡皮参数

## 架构

设置状态以 `LuminaliumConfig` 为唯一事实来源。设置页面 ViewModel 通过统一协调器提交变更；协调器串行更新配置、执行平台或运行时副作用、原子保存，并在失败时恢复旧值。运行中的 Overlay、工具栏、放映监控和自动显示监视器通过设置变更事件读取最新快照。

现有主题、语言、字体和启动画面回调继续复用。新增设置不得在页面 ViewModel 内直接读写 JSON，也不得复制独立配置状态。

## 生效规则

- 主题、强调色、语言、字体、Overlay 布局、工具栏、状态栏、自启动、URL 协议和自动显示 Overlay 在平台能力允许时即时生效。
- 启动画面设置保存后影响下一次启动。
- PPT 翻页频率立即影响后续请求。
- PPT 画笔模式从下一次进入书写状态开始生效，不强制打断当前书写会话。
- 原生标题栏等需要重建窗口的设置不纳入本阶段。
- PowerPoint 翻页继续使用 COM 优先、虚拟键回退；不得在虚拟键发送函数中抢占前台窗口。

## 容错

- 保存失败时恢复 UI 和运行时旧值，并沿用 Shell 错误提示。
- 未知工具 ID 被忽略，缺失工具顺序使用安全默认值。
- 无效枚举、缩放、透明度和时间间隔在配置服务层拒绝。
- 平台服务失败时不保留与系统实际状态不一致的配置值。

## 验证

- 配置加载、保存、校验和失败回滚单元测试。
- 常规与个性化 ViewModel 初始化和变更测试。
- Overlay 与工具栏设置快照、排序、可见性和运行时刷新测试。
- PPT 翻页限流、画笔模式和 COM 优先行为测试。
- Release 构建零错误，并运行全量测试。
