## 现状判断
- Overlay 的页码只会在收到 `monitor.slide_changed` 信号后更新（见 [overlay.py](file:///d:/Documents/Kazuha/ppt_assistant/ui/overlay.py#L2382-L2406)）。
- 在只读/受保护视图下，目前经常进入 Win32 降级路径（`SlideShowWindows.Count == 0`），这时我们只能激活 Overlay 和发送按键，但**没有可靠的 COM 方式拿到当前页/总页**，因此页码一直保持默认值（你截图里的 0/0）。

## 根因
- 只读/受保护视图下，`SlideShowWindows/SlideShowWindow/View` 等 COM 对象可能不可用或不稳定，导致无法持续获取页码。
- 目前 Win32 降级路径只做了窗口定位/几何更新，没有保证一定会发出非 0 的 `slide_changed`。

## 修复思路（保证“可用”优先）
### 1) 降级模式下初始化页码
- 在识别到 Win32 降级并触发 `slideshow_started` 时：
  - 尽力获取 `total`：优先 `ActivePresentation.Slides.Count`；其次 `ProtectedViewWindows(1).Presentation.Slides.Count`。
  - 如果拿到 `total>0` 且当前页未知，则默认 `current=1`，立刻 `emit slide_changed(1, total)`。

### 2) 降级模式下“按键驱动”页码跟随
- 当 Overlay 通过本软件触发翻页/跳转（`go_next/go_previous/go_to_slide`）且 COM 失败转为 Win32 发送按键时：
  - 在本地维护 `current/total` 缓存并同步 `emit slide_changed(current, total)`。
  - 做边界保护：`current` 限制在 `[1,total]`。

### 3) 不影响正常 COM 模式
- 只在 `control_mode == win32` 或 `SlideShowWindows.Count == 0` 的情况下启用上述逻辑；一旦 COM 模式恢复，以 COM 的真实页码为准覆盖本地缓存。

## 验证方式
- 受保护视图打开 PPT → 进入放映：页码应立刻显示 `1/总页数`。
- 用 Overlay 的上一页/下一页：页码同步变化。
- 若用户用鼠标/遥控器在 PPT 内翻页（绕过 Overlay），页码可能仍不同步（受限于无可靠 COM），但“使用 Overlay 控制时一定正确”。
